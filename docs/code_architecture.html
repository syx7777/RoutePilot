RoutePilot 代码架构

这个页面用于快速看清项目代码架构：入口在哪里，Agent 如何协作，核心层和 skills 如何分工， LangGraph 如何编排，以及一次 trial 会落哪些证据产物。

主流程

从已有预测实验到 keep/rollback 决策
Input

已有预测实验

读取预测结果、真实值、训练入口、日志、配置和历史产物。

Skills

扫描与标准化

生成 artifact contract，标准化 prediction 与 actual。

Agent1

评测与诊断

计算指标、拆解场景、定位 badcase，形成问题上下文。

Agent1

实验计划

基于证据生成特征假设、候选实验和 experiment_plan。

Agent2

隔离执行

复制训练入口到 trial 目录，只修改副本并运行训练评测。

Decision

对比与报告

对比新旧 WAPE/Bias，决定 keep 或 rollback，输出最终报告。

代码分层

每一层只做自己的事

CLI 入口

用户命令进入系统。

main.py

单轮实验入口。解析 ask、experiment、provider、model、output 后调用 graph。

loop.py

多轮 trial 外层循环。管理 trial 目录、历史结果、最佳 trial 选择。

program.md

项目规则与边界的权威说明，约束评测、修改范围和 rollback 规则。

编排层

把阶段串成可追踪流程。

orchestrators/langgraph_flow.py

主状态图。定义 evaluate、plan、run、review、report 等节点。

orchestrators/sequential_flow.py

串行入口，目前复用单轮 graph，保留 CLI 兼容与扩展点。

RoutePilotState

节点间状态，只传 artifact path、小对象和状态标记。

Agent 层

LLM 负责研究、计划与复审。

evaluation_hypothesis_agent.py

Agent1：生成诊断、特征假设、候选实验和实验计划。

report_agent.py

Agent2 报告与复审：解释实验效果、输出最终结论。

llm_decision_agent.py

多轮模式中选择最佳 trial，写出 best_trial_review。

Core 层

只处理实验执行侧逻辑。

experiment_plan.py

读取计划并应用受控修改，保护 toy fixture 可编辑边界。

real_experiment_runner.py

真实实验训练 wrapper，复制入口和依赖到 trial 副本。

compare.py

指标对比与 keep/rollback 决策：WAPE、Bias、训练和评测状态。

reports.py

构建最终报告上下文，写出 final_report。

rollback.py

处理 rollback 结果，保证失败方案不污染原实验源码。

schemas.py

Pydantic schema，校验计划、运行状态和报告结构。

Runtime 层

技能、LLM、产物和审计基础设施。

skill_runner.py

调用本地 skills/scripts，完成扫描、指标、场景和 badcase 任务。

llm_client.py

统一 LLM 客户端，支持 provider 推断、responses/chat、重试和 token 统计。

artifact_contract.py

把原始 prediction/actual 转成标准化输入契约。

agent_run_recorder.py

记录 agent 状态、时间线、错误报告和 LLM 调用。

trial_archive.py

把单轮 trial 产物整理成分组目录和 archive 证据包。

cli_summary.py

命令行输出摘要：decision、指标变化、报告路径和 token。

状态传递原则

RoutePilotState 中只保存路径、小型 dict 和状态标记。 大 CSV、DataFrame、完整 prompt 不进入 state，避免图状态膨胀和不可追踪。

artifact path status flag small dict no DataFrame no full prompt

Skills 能力分布

评测能力来自 skills，不在 core 重复实现

发现与分析

  • forecast-experiment-scanner：扫描 CSV、代码、日志、配置。
  • forecast-code-log-analyzer：解析代码结构、argparse、训练日志。
  • forecast-task-planner：解析用户 ask 和 skill 路由。

评测与 badcase

  • forecast-evaluation-analyzer：WAPE、Bias、MAE、RMSE、场景指标。
  • forecast-badcase-locator：最大误差、低估、高估和异常样本。

建议与报告

  • forecast-optimization-advisor：基于证据生成优化建议。
  • forecast-report-writer：写出评测诊断报告。
  • forecast-trial-codegen：trial 代码生成约束参考。

安全边界

项目最重要的约束

通用性边界

  • Agent 和 skills 不写死业务线、套餐、单品或固定模型。
  • 无法识别的模型家族和目标函数标记为 unknown。

评测边界

  • 评测能力来自 skills/。
  • core/ 不新增重复的 forecast 评测工具。

编辑边界

  • 真实实验只在 runs/<trial>/code/ 副本中修改。
  • 不修改 actual、metric definitions 和 data split logic。

决策边界

  • WAPE 至少改善 0.005。
  • abs(Bias) 恶化不超过 0.02。
  • 训练和评测必须成功，否则 rollback。
